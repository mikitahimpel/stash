# CLAUDE.md — apps/mac-agent

Read the root [CLAUDE.md](../../CLAUDE.md) first.

## Purpose

A small Node process on a Mac, run by launchd. It reads open iPhone Safari tabs from the iCloud Tabs
database (`~/Library/Containers/com.apple.Safari/Data/Library/Safari/CloudTabs.db`, which needs
Full Disk Access) and posts snapshots to the API with a per-device API token on a schedule. It is a
context of its own with no `packages/` counterpart.

## May depend on

- `@stash/contracts-*`: call the API with `HttpApiClient` from `@stash/contracts-api`, and use the
  schemas from `@stash/contracts-domain`.
- `@stash/config-*` (dev tooling).
- Third-party packages from the catalog (`effect`, `@effect/platform-node`, a SQLite driver).

Never import `@stash/backend-*`, `@stash/mcp-*`, `@stash/web-*` or `@stash/ext-*`. oxlint enforces
this.

## tsconfig base

`@stash/config-tsconfig/node.json`: ES2024 with `@types/node`. Add `@types/node` (`catalog:`) to
devDependencies.

## Platform

There is no platform package. Use `@effect/platform-node` services (`FileSystem`, `HttpClient`) and
put Node and SQLite access behind small services at the edge (`cloud-tabs-reader.ts`), so the
logic can be tested with in-memory layers.

## Rules

- Open `CloudTabs.db` read-only. Never write to Safari's files.
- The API URL, device token and DB path come from env. The token is a `pass://` reference resolved
  by `pp run`. Never commit it.
- The launchd plist in the repo uses placeholders, not real paths or usernames.

## Testing

Vitest with `@effect/vitest`. Test the reader against a synthetic SQLite fixture (invented devices,
tabs and URLs) generated by the test, never a copy of a real `CloudTabs.db`. Test the poster with
a fake API layer.

- `launchd/com.example.stash-mac-agent.plist`
- `test/cloud-tabs-reader.test.ts`, `test/fixtures/stub-api.ts`
